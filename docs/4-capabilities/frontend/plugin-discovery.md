# Frontend — Plugin Discovery & Routing

> **Layer 4 — Capability** · Audience: developer · Pseudocodice ammesso. Feature: [dynamic-integration](../../3-features/plugins/dynamic-integration.md) · Build: [build-system](../../infrastructure/build-system.md).

## Scopo

Montare dinamicamente i frontend dei plugin abilitati senza modifiche manuali a build o routing.

## Requisiti

- **FDISC-R1** — Il registro `src/generated/plugin-registry.ts` è **generato** dallo step `build:plugins` (legge i manifest, filtra `enabled` con `frontend.entry`), mai scritto a mano.
- **FDISC-R2** — All'avvio la SPA fetcha `GET /api/plugins` e registra una route per ogni plugin: `route_base` → componente lazy dal registro generato.
- **FDISC-R3** — L'entry contract del plugin esporta **solo il componente**; la route viene **esclusivamente** dal manifest (`route_base`), una fonte sola.
- **FDISC-R4** — Mismatch bundle/runtime (plugin in API ma non nel registro o viceversa — capita solo se si è riavviato senza rebuild): la voce è esclusa dalla nav e loggata in console con istruzione esplicita "rebuild necessario". Mai pagina rotta.
- **FDISC-R5** — Le voci della sidebar (gruppo SCRAPERS) derivano dalla stessa discovery: icona dal manifest, nome `display_name`, link a `route_base`.

## Registro generato (forma)

```typescript
// AUTOGENERATED da build:plugins — NON modificare
export const plugins = [
  {
    name: "<plugin_id>",
    route_base: "/plugins/<route>",
    component: () => import("../../plugins/<tipo>/<nome>/frontend/index.ts"),
    i18n: () => import("../../plugins/<tipo>/<nome>/frontend/i18n"),
  },
]
```

## Entry contract del plugin

```typescript
// frontend/index.ts del plugin
export default {
  component: PluginRoot,        // componente Svelte radice (gestisce le sue sub-view)
}
```

## Sequenza runtime

```
boot SPA
  → GET /api/plugins                       (name, type, route_base, icon, display_name)
  → per ogni plugin: lookup nel registro generato per name
      → trovato: registra route (lazy) + voce sidebar (se scraper) + carica namespace i18n
      → assente: log console "plugin X richiede rebuild" (FDISC-R4)
```

Il componente del plugin riceve dal core il contesto UI minimo (utente corrente, locale, client API autenticato) via le store condivise di `$lib`.
